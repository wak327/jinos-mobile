# Concourse: an app-ecosystem-first Linux phone OS

Design date: 2026-10-03. Angle: start from the apps people cannot live without in 2026 and design the OS backward from them. Codename **Concourse** ("one concourse, many gates"): every app, whatever runtime it came from, arrives through the same launcher, notifications, share sheet, permission centre and background policy. Claims marked **unverified** could not be confirmed against a 2025-2026 source.

## 0. Design backward from the must-have apps

| Need (2026) | Reality | Best route on a Linux phone | Gate |
|---|---|---|---|
| WhatsApp | Android/iOS app only; Web needs a registered phone | Android app in a container; push via microG or WhatsApp's own channel, with reported delays ([GrapheneOS forum](https://discuss.grapheneos.org/d/17146-whatsapp-without-google-play), [F-Droid forum](https://forum.f-droid.org/t/push-notifications-without-google/6010)) | Android |
| Signal, Telegram | Native Linux clients exist; Molly (Signal fork) uses UnifiedPush | Flatpak, Android as fallback | Flatpak |
| Banking, PSD2 2FA | Apps increasingly need Play Integrity `MEETS_DEVICE_INTEGRITY`: locked bootloader plus certified image, hardware-attested since May 2025 ([Google](https://developer.android.com/google/play/integrity/improvements), [Android Authority](https://www.androidauthority.com/google-play-integrity-hardware-attestation-3561592/)) | Web banking in a real Chromium; non-gated bank apps in the container | Web, Android |
| Maps | Google Maps web (no turn-by-turn); Organic Maps/PureMaps native; OsmAnd/Google Maps as Android apps | Web, Flatpak, Android | all |
| Camera | Must be native to be good | libcamera (mainline) or HAL3 via droidmedia (Halium) | Native |
| Ride-hailing, delivery | Uber keeps a mobile web client ([Uber](https://www.uber.com/en-IE/blog/request-uber-online-without-app/)); apps run in a container unless gated | Web, Android | Web |
| 2FA, passkeys, FIDO2 | TOTP natively; libfido2; passkeys inside Chromium | Flatpak, Web | Flatpak |
| Tap-to-pay, Google Wallet, EU ID/age wallets | Require certified integrity ([EU age verification mandates hardware attestation](https://discuss.privacyguides.net/t/eu-age-verification-project-mandates-hardware-bound-attestation/39663)) | Impossible on any non-certified OS; say so | none |
| Streaming | Widevine L3 in Chromium gives SD; L1 needs a certified TEE path | Web App Host with CDM | Web |

Three conclusions follow. First, the catalogue a Linux phone can offer in 2026 is **Flathub + the web + Android-in-a-container**; the measurable ecosystem is small but real: Open-Store lists 839 apps, 192 web apps and 352 bookmarks (Jan 2026); LinuxPhoneApps rates 315 libadwaita and 119 Kirigami apps fully mobile-compatible; Flathub has had a mobile collection since January 2025 ([FOSDEM 2026 slides](https://archive.fosdem.org/2026/events/attachments/VH3GYN-linux-phone-app-ecosystem-2026/slides/267147/the-linux_jhotzh9.pdf), [Flathub](https://docs.flathub.org/blog/on-the-go-linux-mobile-collection)). The same talk names banking, government ID and Bluetooth-gadget apps as gaps needing "others' cooperation". Second, the differentiator is not a new home screen but **making those three catalogues feel like one platform**, plus honesty about what cannot work. Third, the native SDK must bring new apps cheaply, so it must be a toolkit mobile developers already use: Flutter, not a new language.

## 1. Hardware adaptation

**Two lanes, one userland.** One Debian-based image family, lane chosen per device:

- **Halium lane (default for 2023-2026 phones):** the OEM's downstream kernel rebuilt from source with a Concourse kconfig fragment, vendor partitions untouched, Android `init` running only HALs inside an LXC container, `libhybris` + `libgbinder` for in-process and binderized HALs. It is the only route to phones younger than about three years: UT's Fairphone 5 port reaches 97.4% with camera, fingerprint, NFC, calls and data ([UT device page](https://devices.ubuntu-touch.io/device/FP5/release/noble)). The port key is the vendor API level, not the Android version: FP5 runs Android 15 on VNDK 30 ([UBports forum](https://forums.ubports.com/post/89132)).
- **Mainline lane (SDM845 now, QCM6490 as it matures):** close-to-mainline kernel, DRM/KMS + Mesa, ModemManager over QRTR, libcamera. Debian trixie already runs OnePlus 6/6T on a 6.12 kernel ([Mobian](https://blog.mobian-project.org/posts/2025/10/new-stable-rotating-keys/)).

**Treble/GSI.** We use the generic Halium system image (Droidian's `halium_arm64` lineage) on GSI-capable devices, so per-device work is a kernel defconfig plus a Debian *adaptation package* (udev, audio quirks, sensor and display quirks), the Droidian/FuriLabs model. Android base: Halium 11-14 vendor partitions today; UBports is reported to be integrating Halium 16-based ports ([Phoronix](https://phoronix.com/news/Ubuntu-Touch-Toward-26.04); scope **unverified**), which we follow rather than lead. Android 15+ vendor partitions drop the VNDK and move libraries into APEX ([AOSP](https://source.android.com/docs/core/architecture/vndk)); whether libhybris copes is open, which is why we start on VNDK 30-33 devices.

**Subsystem paths (Halium / mainline):** GPU: hybris EGL/GLES and hybris Vulkan (demonstrated by UBports in March 2026, shipped by FuriLabs) / Mesa Turnip. Research track: Turnip on the downstream KGSL driver ([Phoronix](https://www.phoronix.com/news/TURNIP-KGSL-Vulkan-Bringup)) could give glibc processes upstream Vulkan without bionic; **unverified**, not a dependency. Display: hwcomposer via libhybris / DRM/KMS. Modem: oFono + `ofono-binder-plugin`, with Droidian's `ofono2mm` exposing the ModemManager D-Bus API so GNOME Calls, Chatty and Settings work unchanged ([Droidian forum](https://forum.droidian.org/t/issues-with-cellular-data/75)) / ModemManager 1.24 + libqmi. Camera: `droidmedia` + `gst-droid` / `qcom-camss` + libcamera, both exposed as PipeWire camera nodes. Audio: `pulseaudio-modules-droid` first, a PipeWire SPA droid plugin later / PipeWire + callaudiod + `q6voiced`. Sensors: `sensorfw` behind an `iio-sensor-proxy`-compatible shim / `iio-sensor-proxy`. Haptics, LEDs, fingerprint: vendor HALs via libgbinder / feedbackd.

**Device policy.** Primary: Fairphone 5 (QCM6490, kernel 5.4, VNDK 30, both lanes exist) and Fairphone (Gen. 6) (SM7635, `android14-6.1` GKI, Android 15, kernel and devicetree sources published ([code.fairphone.com](https://code.fairphone.com/projects/fairphone-gen-6/kernel.html)); UT's Halium 14 port only just started ([UBports forum](https://forums.ubports.com/post/94806))). Secondary: SHIFTphone 8 (same QCM6490), Volla Quintus/FuriLabs FLX1s (MediaTek, proven IMS). Developer-only: Pixel 8/9 (Mali G715 means libhybris-only graphics; relockable, but kernel source is now behind a Google form ([Android Authority](https://androidauthority.com/google-pixel-kernel-code-forms-3696441/))) and OnePlus 12/13 (unlockable globally today; the ColorOS 16 identity-verified quota policy is spreading ([Notebookcheck](https://www.notebookcheck.net/OnePlus-tightens-ColorOS-bootloader-unlock-policy-adds-device-quota-and-14-day-expiry-window.1350758.0.html))). Excluded: Pixel 10 (DXT GPU unsupported by Mesa), Samsung (unlock removed in One UI 8), Xiaomi. The user's OnePlus 6 is the mainline-lane development and hardware-CI device.

## 2. Boot, kernel, init, updates

**Kernel.** Halium lane: OEM tree plus `concourse.config`: binderfs with multiple devices, `CONFIG_USER_NS` (bubblewrap and Chromium's sandbox), cgroup v2 freezer, fscrypt v2, Landlock where the base is 5.13+ (FP6's 6.1 yes, FP5's 5.4 no), BPF; vendor `.ko` modules stay binary. GKI devices use the KMI-stable ACK branch so LTS fixes land without per-device backports ([AOSP GKI](https://source.android.com/docs/core/architecture/kernel/generic-kernel-image)). Mainline lane: Nura's generic `linux-stable/lts` pattern, fragment configs, upstream-bound patches only.

**Init and initramfs.** systemd on both lanes. `concourse-initrd` is a dracut module derived from Droidian's `initramfs-tools-halium`: find the active slot, open dm-verity on the root image, mount `/vendor`, `/odm`, firmware and `persist` into the Android LXC rootfs, hand off to systemd; it handles legacy `boot.img` and GKI `boot` + `init_boot` + `vendor_boot` layouts.

**Partitions and A/B.** We keep the OEM's slot machinery. `boot_a/_b` hold kernel plus our initramfs; root slots are the OEM's `system_a/_b` logical partitions inside `super`, resized once at install; `vendor_a/_b` stay as flashed. The root is an EROFS image with a dm-verity hash tree whose root hash rides in the kernel command line, so boot and root slots are always updated as a pair. `/etc` is a writable overlay seeded from the image (systemd-confext for overrides); `/var` and `/home` live in `userdata` under fscrypt v2. Mainline lane: Duranium's layout (EROFS + dm-verity + A/B inside `userdata` via U-Boot `blkmap`, UEFI/UKI) ([Nura](https://nura.eco/blog/2026/03/17/introducing-duranium/)).

**Slots.** A Go daemon, `slotctl`, implements Android `boot_control` semantics on the `misc` bootloader control block: set active, mark successful after `concourse-boot-complete.target`, mark unbootable after N failed boots so ABL falls back. AVB rollback indexes are bumped only after the slot is marked successful ([U-Boot AVB docs](https://docs.u-boot.org/en/latest/android/avb2.html)).

**OTA.** One updater on both lanes: **RAUC 1.15**, signed verity-format bundles streamed over HTTPS, adaptive deltas, `raw` slot types, and the `custom` bootloader backend driving `slotctl` ([RidgeRun's example](https://developer.ridgerun.com/wiki/index.php/RidgeRun_Platform_Security_Manual/Getting_Started/Over-the-Air/NVIDIA_Jetson_-_RAUC/Update_Flow_and_Custom_Bootloader)). systemd-sysupdate (262 adds a Varlink API) is the fallback; GNOME OS and Duranium use it. Channels `edge/beta/stable`, six-month releases. Vendor firmware: a phase-4 fetcher downloads the OEM's own OTA package, extracts `vendor/odm/modem/dtbo/vendor_boot` and writes them to the inactive slot; we never redistribute blobs.

**Verified boot.** Default ORANGE. On devices with a user-settable root of trust we sign `vbmeta` with the Concourse key and relock to YELLOW: Pixels via `avb_custom_key`; Fairphone exposes an `avb_keys` mechanism that iodéOS uses, but the community guide records "device is corrupt" failures and bricks between `lock_critical` and `lock` ([Fairphone forum](https://forum.fairphone.com/t/guide-to-bootloader-and-bricking-2025/121352), [iodé forum](https://community.iode.tech/t/close-the-bootloader-back-on-fp5/8135)). Relock is opt-in per device after passing hardware CI on three units. No Linux-phone project ships this chain today; it is the precondition for section 8's attestation story.

## 3. Base system

- **Debian 13 "trixie"** plus a Concourse overlay repo for backports (systemd 262, Flatpak 1.18, xdg-desktop-portal 1.22, PipeWire 1.6, ModemManager 1.24, libcamera 0.7, phoc/Phosh 0.57+, Qt 6.11/QtWebEngine 6.140, Waydroid 1.6.3, Droidian's Halium middleware). Reasons: Droidian/FuriOS already package libhybris, libgbinder, oFono binder plugins, `ofono2mm`, `pulseaudio-modules-droid`, droidmedia and the phoc hwcomposer fork for Debian; Mobian supplies mainline-lane device packages; Debian ships Chromium and `qt6-webengine` as ordinary arm64 packages (Ubuntu's Chromium is snap-only); stable moves slowly enough for a tiny team. Not Alpine/musl: libhybris, the Flutter engine, Chromium and `gbinder-python` assume glibc, and Oniro called musl+libhybris a "workaround, not ideal".
- **libc** glibc; **init** systemd.
- **Build:** **mkosi** v27 (Aug 2026; Debian images, EROFS+verity DDIs, sysext/confext, signing) for the root ([Debian changelog](https://tracker.debian.org/media/packages/m/mkosi/changelog-26-4), [Arch](https://archlinux.org/packages/extra-testing/any/mkosi/)); a Go tool `concourse-image` wraps `mkbootimg`, `avbtool`, `lpmake` and RAUC bundling. apt exists only at build time; optional layers (debug tools, Waydroid images) are `systemd-sysext` images.
- **Apps:** Flatpak only (section 6). Snaps are not used: strict confinement needs Ubuntu's AppArmor patches, absent from vendor kernels, and the mobile catalogue is on Flathub. We borrow snap's ideas (interfaces, `revert`, deltas), not its runtime.

## 4. Graphics and compositor

**Compositor: phoc (wlroots).** Upstream phoc on mainline; Droidian's wlroots/phoc fork with the libhybris hwcomposer backend on Halium (FuriOS ships it; it lags upstream wlroots by two to three versions: 0.17.4 in Droidian 101 against 0.20.2 ([Droidian branches](https://github.com/droidian/wlroots/branches))). It is the only maintained Path-B compositor that is not Qt5 Mir. Rejected: Mir 1.8 + `mir-android-platform` (Lomiri/Qt5-bound, Mir 2 move has taken years); KWin (hwcomposer removed in 2020, [KWin MR 551](https://invent.kde.org/plasma/kwin/-/merge_requests/551)); Smithay (no hwcomposer backend); **Qt Wayland Compositor**, the earlier suggestion: no Qt6 hwcomposer QPA (Sailfish's is Qt5), GPLv3-or-commercial ([Qt docs](https://doc.qt.io/qt-6/qtwaylandcompositor-index.html)), and we would be the first Qt6 phone compositor. Qt6 stays first-class for apps. Long term we work toward a proper out-of-tree wlroots hwcomposer backend instead of a fork; Smithay is plan B.

**GPU userspace.** Mainline: Mesa 26.x (Turnip Vulkan 1.3/1.4 conformant on Adreno 6xx/7xx, Gen 8 landing, [Mesa 26.0](https://docs.mesa3d.org/relnotes/26.0.0.html)). Halium: hybris GLES for GTK4/Qt6/Flutter, hybris Vulkan where the vendor ICD cooperates, Turnip-on-KGSL as research. This matters for the SDK: Flutter 3.47 made Impeller default on Linux and Impeller targets Vulkan there ([startdebugging](https://startdebugging.net/2026/08/flutter-3-47-impeller-default-renderer-on-desktop/)); our embedder must offer the GLES backend as fallback, and `--no-enable-impeller` is documented as temporary.

**Composition.** The hwcomposer backend lets the display HAL scan out the compositor buffer; no per-layer overlay offload in phase 1. Waydroid renders via Mesa (mainline) or hybris gralloc/EGL (Halium), each Android app as its own `xdg_toplevel`.

## 5. Shell and the user-experience differentiator

**Shell: Phosh, adopted not forked.** Phosh 0.57 (Aug 2026) brings a unified settings app, plugins, the Stevia OSK, `phrog`/greetd login and `gmobile` notch quirks ([Phosh](https://phosh.mobi/posts/development-news-2026-08/)). The shell is not where this OS wins; phase-1 shell work is a theme, a lockscreen plugin and quick-settings tiles. **Decision gate at month 14:** if the Flutter embedder (section 6) is solid, prototype a Flutter layer-shell shell on phoc. Denial WM (Aug 2026, a Rust compositor with an embedded Flutter engine, alpha) proves the model but has no hwcomposer backend ([denialwm/denial](https://github.com/denialwm/denial)), so it informs only the mainline lane.

**The differentiator: every app is a first-class citizen, and we tell the truth.**
1. **One launcher, notification stream, share sheet, permission centre, clipboard and URL-handler registry** across Flatpak, web, Android and native apps. Android notifications arrive through Waydroid 1.6's D-Bus notification manager, which needs a matching Android image and `python-gbinder` 1.3+ and was reported not working on the default LineageOS image at release ([Ubuntu Handbook](https://ubuntuhandbook.org/index.php/2025/11/waydroid-1-6-0-forward-notifications-to-desktop/)), so the Bridge's in-container listener is the fallback; PWA notifications through QtWebEngine's hook; Flatpaks through the portal. A runtime badge on each icon shows where an app runs.
2. **App Compass:** a built-in, crowd-sourced compatibility index (native / web app / Android gate / fails integrity) plus a Flutter companion app for the user's *current* Android phone that reads the installed-app list and answers "will my life work on Concourse?" before they switch.
3. **Migration assistant:** APK and data transfer from the old phone (local WhatsApp backup restore, vCard/iCal, photos), so day one is not empty.
4. **Gate policies per app:** Always-on, Freeze-when-idle, Manual, with battery cost shown (section 7).

## 6. App model

**Gate A: Flatpak** (GTK4/libadwaita, Qt6/Kirigami, anything). Flatpak 1.18 + bubblewrap + xdg-desktop-portal 1.22 ([Flatpak 1.18.4](https://github.com/flatpak/flatpak/releases/tag/1.18.4), [portals](https://github.com/flatpak/xdg-desktop-portal/releases)). Remotes: Flathub (mobile collection first) and `concourse-apps`. Portals are the *only* path to user data (OpenHarmony's picker rule); `xdg-desktop-portal-concourse`, forked from `-phosh`, consults one permission service.

**Gate B: Web App Host.** A Qt 6.11 process on **QtWebEngine 6.140 (Chromium 140)** ([Qt blog](https://www.qt.io/blog/qt-webengine-will-release-separate)). Each web app gets its own `QWebEngineProfile`, a launcher entry from its manifest, Web Push through `setPushServiceEnabled` (Chromium's FCM channel: no Google account, but Google servers, stated plainly) ([Qt example](https://doc.qt.io/qt-6/qtwebengine-webenginewidgets-push-notifications-example.html)), notifications and permission prompts routed to `concourse-permd`, a `navigator.share` polyfill into the share sheet, and optional Widevine CDM loading. Not WebKitGTK: no Web Push ([WebKit bug 245190](https://bugs.webkit.org/show_bug.cgi?id=245190)) and weaker banking compatibility. Not Servo as default: 0.4.0 (July 2026) renders Google Photos and Zulip and the `servo` crate is embeddable, but it is not banking-grade; it becomes an experimental engine option ([Phoronix](https://www.phoronix.com/news/Servo-Embed-Crates-LTS)). Web apps are `*.webapp.toml` declarations installed from the browser's Install action or App Compass.

**Gate C: Android, integrated deeply.** **Waydroid 1.6.3** (Android 13 LineageOS 20 images, initial Android 16 support; LineageOS 23.x community images exist) ([releases](https://github.com/waydroid/waydroid/releases), [Android 16 builds](https://newreleases.io/project/github/WayDroid-ATV/waydroid-builds/release/20260717)) with microG preinstalled (FCM push, maps compat, network location) and Aurora Store plus F-Droid as the only install paths; we redistribute no APKs. The **Android Bridge** (Go daemon plus a privileged in-container companion app) adds launcher icons, notification forwarding with actions, URL/intent handling both ways (App Links can target PWAs or Flatpaks and vice versa), clipboard sync, host geoclue location into the container, a UnifiedPush proxy so apps like Molly ride the host's single push socket, and the freezer policy. Stated limits: camera and sensor conflicts with the HAL container (UBports documents this, [UBports docs](https://docs.ubports.com/en/latest/userguide/dailyuse/waydroid.html)); WhatsApp notifications without microG can lag minutes; integrity-gated apps fail. Sailfish AppSupport shows what deeper integration buys (Bluetooth passthrough, Android 15) but is closed; FuriLabs' `andromeda` fork is the closest open relative, feature set **unverified**.

**Gate D: native SDK = Flutter.** Flutter 3.47+/Dart 3.12+ with a **Concourse Wayland embedder** (C++, from Sony's BSD-3 `flutter-embedded-linux` Wayland backend ([GitHub](https://github.com/sony/flutter-embedded-linux)), adding `text-input-v3`, `fractional-scale`, `xdg-decoration`, `wlr-layer-shell`, Impeller Vulkan with GLES fallback), **Dart packages wrapping portals and services** (`concourse_portals`: camera via PipeWire, location, files, share, notifications, background jobs; `concourse_telephony` over ModemManager D-Bus), `material_ui`/`cupertino_ui` 1.0 as ordinary packages, and a `concourse sdk` CLI that emits a Flatpak manifest (`org.freedesktop.Platform` 25.08, engine bundled per app as Android does, about 12 MB). Why Flutter: the largest cross-platform mobile developer pool, declarative UI (what ArkUI offers without inventing a language), hot reload, AOT, and the pay-off that Android/iOS Flutter apps port in days while Concourse apps ship back to Android/iOS. Alternatives: Qt6/QML is supported but C++-centric and brings no new developers; GTK4/libadwaita is the best existing mobile Linux app base and stays first-class; Slint's royalty-free licence excludes "embedded" and needs written confirmation ([Slint licence](https://github.com/slint-ui/slint/blob/master/LICENSE.md)); ArkTS/ArkUI needed Huawei-scale staffing; Tauri on Linux means WebKitGTK; React Native and Compose Multiplatform have no Linux mobile story. TypeScript developers get Gate B with standard web APIs, never a proprietary `navigator.concourse`; installable web apps are borrowed from Firefox OS and webOS, their custom Web APIs are not ([Ben Francis](https://medium.com/@bfrancis/the-story-of-firefox-os-cb5bf796e8fb)).

**Sandbox, permissions, identity.** Every app runs in its own cgroup slice (`app-flatpak-<id>`, `app-web-<id>`, `waydroid`) with a stable **app token** derived from slice plus app ID (OpenHarmony's TokenID, Flatpak's `/.flatpak-info`). `concourse-permd` is the single authority for "does token T hold permission P", with persisted, one-time and session-scoped grants (Android 15-17 UX) and a per-app **network toggle enforced by nftables cgroup matching**, which Flatpak alone cannot do. Portals, the Web App Host and the Bridge all ask it. Store apps follow UT's click rule: bundle everything ([UT click](https://docs.ubports.com/en/latest/appdev/platform/click.html)).

## 7. Telephony, audio, camera, sensors, power

- **Telephony:** apps see ModemManager D-Bus on both lanes (`ofono2mm` on Halium); GNOME Calls (speaks MM and oFono), Chatty, `mmsd-tng`. VoLTE: vendor IMS via the oFono binder plugin on Halium (working on MediaTek, carrier-dependent on Qualcomm radio HAL 1.5+); `openimsd` beside ModemManager on mainline ([openimsd](https://www.openimsd.de/)), still experimental. Devices are chosen where UT or FuriOS already have IMS working. eSIM: `lpac` + `lpa-gtk` where the modem exposes APDUs ([lpac](https://github.com/estkme-group/lpac)). RCS: unavailable, said plainly. Cell Broadcast via ModemManager 1.24.
- **Audio:** PulseAudio + `pulseaudio-modules-droid` (Halium) and PipeWire + callaudiod + `q6voiced` (mainline, [Nura](https://nura.eco/blog/2026/05/08/q6voice-project/)) in phase 1; a PipeWire SPA droid plugin in phase 4 so one server serves both lanes.
- **Camera:** PipeWire camera nodes (gst-droid wrapper / libcamera SPA) behind the Camera portal; a Flutter camera app in phase 3 (Megapixels until then). Expectation: "basic HAL3 capture" on Halium, "grainy SoftISP improving" on mainline.
- **Sensors, haptics, NFC:** sensorfw/iio-sensor-proxy, feedbackd, `nfcd` with the binder plugin or kernel NFC.
- **Power:** phase 1 reuses FuriLabs' `batman`-style screen-off suspend (repo listed in their org; details **unverified**). Phase 3 `concourse-powerd` (Go): owns `/sys/power/wakeup_count` autosleep, exposes wakelocks over D-Bus, freezes app slices with the cgroup v2 freezer, batches wakeups into maintenance windows (Doze), and keeps **one** host push socket via a UnifiedPush distributor (D-Bus spec; KUnifiedPush exists, [F-Droid](https://f-droid.org/2026/01/08/unifiedpush-5-years.html)). Android apps use microG's single FCM socket or the proxy; the Web App Host's FCM channel is the one extra socket we accept. Standby target: UT-on-FP5 parity (1-2 days) with the Android gate frozen, unknown until measured.

## 8. Security and privacy model

- **Boot and storage:** dm-verity root, signed RAUC bundles, AVB YELLOW where validated, fscrypt v2 with three classes modelled on OpenHarmony's EL levels ([OpenHarmony](https://gitcode.com/openharmony/docs/blob/master/en/application-dev/file-management/app-sandbox-directory.md)): device-encrypted (alarms, incoming-call UI before first unlock), credential-encrypted (default), lock-evicted (keys dropped on lock). Keys derived through the KeyMint HAL in the Halium container where available (phase 4, feasibility **unverified**), passphrase-only otherwise.
- **Isolation:** Flatpak/bubblewrap + seccomp, Landlock on 5.13+ kernels ([Landlock](https://docs.kernel.org/userspace-api/landlock.html)), Chromium's sandbox for web apps, LXC namespaces for Waydroid, per-app network toggle. The HAL container runs the vendor SELinux policy *permissive* like every Halium port; enforcing mode is phase-4 research because Android's hardening assumes a labelled `servicemanager`.
- **Attestation reality.** Since May 2025 `MEETS_DEVICE_INTEGRITY` needs a locked bootloader with a certified image and `MEETS_BASIC_INTEGRITY` needs platform key attestation. A Linux OS is never certified, so Play Integrity fails in the Android gate (basic integrity almost certainly too; **unverified** per app): Google Wallet, many banks, EU identity and age wallets, Widevine L1. Response: (1) web banking via the Web App Host and App Compass warnings before purchase; (2) no spoofing, which Google detects and GrapheneOS refuses ([GrapheneOS](https://grapheneos.org/articles/attestation-compatibility-guide)); (3) phase 4: pass the device's real KeyMint attestation into Waydroid's keystore so apps following GrapheneOS's direct-attestation guide can accept a published Concourse key (`attestation.json`), valuable only on relocked devices; (4) join GrapheneOS and F-Droid in regulatory advocacy; the July 2026 DMA decision says nothing about alternative-OS certification.
- **Privacy:** no telemetry, opt-in crash reports, microG not GMS, DNS-over-TLS and MAC randomisation by default, portal-scoped storage, session-scoped contact and location grants, Private Space (second user plus separate Waydroid profile) in phase 4.

## 9. Developer experience and build infrastructure

- **A device port is a repo** `device-<vendor>-<codename>`: `device.toml` (codename, SoC, lane, vendor API level, kernel source and fragment, partition map, DPI and `gmobile` quirks, audio/sensor quirks, firmware extraction rules), `adaptation/` Debian packaging, `tests/` (XTS-like smoke suite: boot, modem registration, call audio, camera frame, suspend/resume, OTA round-trip). A `dint`-style validator checks the schema and emits the device page. Tiers testing/community/main with machine-checked criteria and three-month archival copy Nura.
- **One CLI, `concourse` (Go):** `init`, `build` (mkosi + concourse-image), `flash`, `ssh`, `logs`, `doctor`, `update push`, `sdk create|run|build|publish`, `webapp add <url>`.
- **Shell on a desktop:** `concourse sim` runs phoc nested under any Wayland desktop with Phosh, the Web App Host, `concourse-permd` and Waydroid (x86_64 images on Mesa, `binder_linux` module), so UI, bridge and portal work need no phone. A QEMU `virt` image (arm64/x86_64, virtio-gpu) is the CI target and contributor on-ramp.
- **CI:** GitLab pipelines build nightly images, run the smoke suite in QEMU, build Flatpaks, sign RAUC bundles, publish channels. Hardware CI from phase 4 on CI-tron and Nura's open phone harness ([Nura](https://nura.eco/blog/2026/02/10/fosdem-and-hackathon/)), OnePlus 6 and FP5 racked first.
- **Policy:** a written generative-AI contribution policy from day one, since Nura forbids AI-generated contributions ([Nura](https://nura.eco/blog/2026/02/26/pmOS-update-2026-02/)) and we must upstream kernel, Mesa, libcamera and wlroots work.

## 10. What is borrowed and what is not

| Reference | Borrowed | Not borrowed, and why |

## 11. Phased roadmap (1-3 people)

Assumes one full-time developer in phases 0-2, two or three later; part-time halves velocity.

- **Phase 0, months 0-1: skeleton.** Repos, mkosi Debian image booting in QEMU and on the OnePlus 6 with Mobian's kernel and device package, Phosh, nightly CI, decision records.
- **Phase 1, months 1-4: "One Concourse" on mainline.** Flatpak with the Flathub mobile collection; Web App Host MVP; Waydroid + microG + Bridge MVP (icons, notifications, URL handling, clipboard); `concourse-permd` v0; App Compass v0; `concourse sim`.
  **First milestone (month 4): on a OnePlus 6 running Concourse, WhatsApp (Android gate), a real bank's web app installed as a PWA (web gate) and Telegram Desktop or Fractal (Flatpak gate) run side by side with one launcher, one notification stream, one share sheet and shared URL handling, while GNOME Calls and Chatty make calls and send SMS over the modem.** This proves the app-model thesis on hardware that needs no new enablement. It is a contributor demo; nothing is announced as a product until phase 2 ends (the Palm, Ubuntu Edge and Librem 5 lesson).
- **Phase 2, months 4-10: current hardware.** Halium lane on Fairphone 5 reusing UT's device tree and 5.4 kernel with Droidian middleware; RAUC A/B on `super`; installer pulling blobs from the device; Waydroid on Halium with a binder device plan; gst-droid camera into PipeWire; audio routing; standby measurement. **Second milestone (month ~10): FP5 daily-driver candidate** with calls, SMS, data, VoLTE where the carrier allows, camera, Wi-Fi, Bluetooth, GPS, OTA with rollback, 1.5-day standby.
- **Phase 3, months 8-14, overlapping: SDK and store.** Concourse embedder, `concourse_portals`, SDK 1.0, Concourse Store (Flathub + web apps + Android via Aurora/F-Droid), App Compass companion app, migration assistant, `concourse-powerd` v1. Shell decision gate at month 14.
- **Phase 4, months 12-20: trust and depth.** AVB relock on validated devices, KeyMint-backed keys and attestation passthrough with `attestation.json`, vendor firmware fetcher, PipeWire droid plugin, SELinux-enforcing HAL container research, Fairphone (Gen. 6) on Halium 14/16, SHIFTphone 8 reuse, hardware CI with two devices.
- **Phase 5, months 18-30: institution.** Non-profit foundation; CRA readiness (reporting duties since 11 Sep 2026, full obligations 11 Dec 2027 for anyone selling preinstalled hardware, [EU](https://digital-strategy.ec.europa.eu/en/factpages/cyber-resilience-act-implementation)); a hardware partner that preinstalls (Volla/FuriLabs/Fairphone pattern); `main` tier on one device.

## 12. Top risks and mitigations

1. **libhybris/Halium falls behind Android 15/16 vendor partitions** (APEX, no VNDK). Start on VNDK 30-33 devices, follow UBports' Halium 16 work, shrink the hybris surface via Turnip-on-KGSL research, keep the mainline lane alive for FP5/FP6.
2. **Attestation gating keeps spreading.** Not solvable alone: web-first banking, App Compass honesty, attestation passthrough plus published keys, coalition advocacy, never spoofing.
3. **Flutter on Linux is unfinished for phones** (official GTK embedder still without native Wayland support, Impeller defaults to Vulkan, Google stewardship). Own embedder on Sony's base with GLES fallback; GTK4 and Qt6 stay first-class so SDK slips never block the OS; engine bundled per app.
4. **Two Android userspaces on one phone** (memory, battery, camera conflicts). Freezer gate policies, binderfs device plan, 8 GB+ devices, camera arbitration in the Bridge.
5. **One developer, broad scope.** Adopt Phosh/phoc, Droidian middleware and Debian wholesale; strict phase gates; first milestone needs no hardware enablement; recruit around the SDK and Bridge, which are bounded and attractive.
6. **VoLTE on Qualcomm Halium stays flaky** while 2G/3G shut down. Pick devices and carriers where UT already has IMS; MediaTek partner device (Volla) as plan B; track `openimsd`.
7. **Bootloader and source policies drift** (OnePlus quotas, Pixel forms, Samsung lock). Fairphone/SHIFT/Volla focus; generation from factory images; Pixel and OnePlus only in the testing tier.
8. **Legal exposure:** vendor blobs, Widevine CDM, Play APKs. On-device extraction only, CDM as a user-initiated download, Aurora/F-Droid inside the container.
9. **Web push depends on Google's FCM** (QtWebEngine). Documented; UnifiedPush for native apps; a QtWebEngine push-endpoint patch when the team is larger.
10. **Security-update cadence for Chromium/Qt/Flatpak on a tiny team.** Debian security plus QtWebEngine's independent release train, automated rebuilds, RAUC channels, SBOM from the first image.
11. **Camera quality ceiling.** Set expectations publicly; fund libcamera tuning as upstream ISP work lands; never market the camera until it earns it.
